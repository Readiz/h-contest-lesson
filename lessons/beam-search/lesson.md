# 빔 서치와 평가 함수

답이 "행동을 차례로 정해 가는 열"인 문제에서는 해를 앞에서부터 한 단계씩 만듭니다. 한 단계마다 후보를 하나만 남기면 탐욕이고 모두 남기면 완전 탐색입니다. 빔 서치는 그 사이에서 한 단계마다 상태를 `W`개(폭)만 남기고, 남은 상태마다 행동을 하나씩 더해 다시 `W`개로 추리는 일을 끝까지 반복합니다. 무엇을 남길지는 평가 함수(지금까지 얻은 것 + 앞으로 얻을 것의 추정)가 정합니다. 이 강의는 그 틀, 평가 함수의 설계, 같은 상태 합치기, 다양성, 복사 비용을 문제에 상관없이 쓸 수 있는 형태로 다룹니다. 예시는 격자 수집(주)과 순서 문제를 "다음 점을 하나씩 정하는" 순차 결정으로 본 것, 두 가지 연습용 입력입니다.

[문제를 상태·행동·점수로 옮기기](https://h.readiz.com/learn/problem-modeling)와 [초기해 만들기](https://h.readiz.com/learn/construction-heuristics)를 읽었다고 가정합니다. 완성된 해를 조금 바꿔 개선하는 방법은 [근방 설계와 차분 평가](https://h.readiz.com/learn/neighborhood-and-delta)와 [언덕 오르기와 담금질](https://h.readiz.com/learn/hill-climbing-and-annealing), 상대가 있는 게임은 [미니맥스와 알파-베타](https://h.readiz.com/learn/minimax-alpha-beta), 정보가 가려진 문제는 [정보가 부분적일 때 결정하기](https://h.readiz.com/learn/partial-information), 후보를 줄이는 자료구조는 [후보 줄이기와 시간 예산](https://h.readiz.com/learn/candidate-and-time-budget)에서 다룹니다.

## 이 강의에서 다루는 것

- 순차 결정 문제의 구조(상태는 요약, 행동, 단계)와 한 단계의 네 가지 일(평가, 합치기, 추리기, 상태 만들기), 폭·깊이·단계당 평가 횟수.
- 폭 1(탐욕)과 폭 무제한(완전 탐색) 사이, 작은 입력에서의 최적과의 차이, 폭을 늘려도 항상 좋아지지는 않는다는 실측.
- 평가 함수 설계: 지금까지 + 앞으로의 추정, 추정이 없을 때 생기는 일, 추정을 만드는 방법(낙관적 합·거리 벌점·가까운 값의 합·탐욕 완성), 단위 맞추기, 추정의 비용과 폭의 교환.
- 같은 상태 합치기(상태의 키, 해시 또는 정렬 후 인접 비교)와 다양성(묶음별 상한, 흔들기), 복사 비용과 (부모, 행동) 기록으로 경로 복원.
- 경로 재생·키 대조·작은 입력의 최적·손계산 대조 검사와 흔한 실수 5가지.

## 판단 기준 요약

| 상황 | 선택 |
| --- | --- |
| 답이 행동의 열이고 중간 상태를 점수로 비교할 수 있다 | 빔 서치. 폭은 연산 예산에서 정한다 |
| 서로 다른 행동의 열이 같은 상태로 모인다 | 상태의 키를 정해 합친다. 키에 빠진 것이 없는지 작은 입력에서 대조한다 |
| 폭 1이 맴돌거나 동점이 많다 | 추정을 넣되 점수와 단위를 맞추고, 같은 연산 수의 넓은 폭과 비교한다 |
| 평가가 앞을 못 본다(비용만 비교하는 순서 문제) | 폭을 키우기보다 평가를 고친다. 비싼 평가는 상위 후보에만 한다 |
| 상태가 크고 단계가 많다 | 경로를 상태에 넣지 않고 (부모, 행동)을 기록한다 |
| 완성된 해를 조금씩 고친다 | 빔 서치가 아니라 지역 탐색이다 |
