# 후보 줄이기와 시간 예산

입력이 커지면 근방 전체를 한 번 훑는 것만으로 연산 상한을 넘습니다. 점 10,000개의 순서 문제는 구간 뒤집기 근방이 49,995,000개이고, 이동 하나를 아무리 싸게 평가해도 훑기에 연산이 2.5 × 10⁸ 가까이 듭니다. 이 강의는 쓸 방법을 구현 전에 연산 수로 고르는 예산표, 근방을 가까운 후보로 줄이는 이웃 목록과 좌표 칸, 줄여서 놓치는 이동을 재는 방법, 예산을 단계로 나누고 남은 비율에 묶는 틀, 시계를 읽는 비용을 문제에 상관없이 쓸 수 있는 형태로 다룹니다. 예시는 순서를 정하는 문제와 작업을 기계에 배정하는 문제, 두 가지 연습용 입력(순서 `N = 2,000`·`10,000`, 배정 `N = 2,000`, `M = 200`)입니다.

[문제를 상태·행동·점수로 옮기기](https://h.readiz.com/learn/problem-modeling), [초기해 만들기](https://h.readiz.com/learn/construction-heuristics), [근방 설계와 차분 평가](https://h.readiz.com/learn/neighborhood-and-delta)를 읽었다고 가정합니다. 차분 유도는 3번 강의, 온도를 남은 비율에 묶는 구체적인 값은 [언덕 오르기와 담금질](https://h.readiz.com/learn/hill-climbing-and-annealing), 실험 설계 일반론은 [실험과 튜닝](https://h.readiz.com/learn/experiments-and-tuning)에서 다룹니다.

## 이 강의에서 다루는 것

- 입력 상한에서 `준비 + 평가 × 횟수 + 적용 ≤ 연산 상한`을 세는 예산표와 초당 연산 수를 자기 환경에서 재는 방법.
- 점마다 가까운 `k`개의 이웃 목록, 좌표 칸으로 목록 만들기, 전수 목록과의 대조, 칸 한 변과 연산의 관계.
- 후보를 줄였을 때 놓치는 이동과 재는 세 방법(최선 이동이 후보 안인가, 개선량 비율, 후보 지역 최적에서 남은 개선 이동).
- 초기해·탐색·마무리의 예산 배분, 값을 남은 비율에 묶기, 예산을 2배씩 늘릴 때의 곡선, 시계 읽기 간격과 상한 넘침.

## 판단 기준 요약

| 상황 | 선택 |
| --- | --- |
| 근방 한 번 훑기가 예산 안에 여러 번 들어간다 | 줄이지 않는다(전수가 단순하고 놓침이 없다) |
| 한 번 훑기가 예산 규모이거나 넘는다 | 가까운 후보로 줄인다. 목록 만들기 연산도 예산에 센다 |
| 목록을 전수로 만들면 예산을 넘는다 | 좌표 칸으로 만들고 전수 목록과 대조한다 |
| 후보 수를 정해야 한다 | 고정 상수로 두지 않고 빠듯한 예산과 넉넉한 예산에서 비교한다(이 실험: 빠듯하면 4~8, 넉넉하면 16~32) |
| "후보 안에서 더 좋아지지 않는다" | 후보 근방의 지역 최적일 뿐이다. 전체 근방에서 확인한다 |
| 시계를 읽어야 한다 | 간격을 시계 비중과 상한 넘침 두 쪽에서 정한다 |

## 대표 실험

## 본문

1. [원리: 연산 수 예산, 후보 목록, 놓치는 이동, 시간 배분](pages/idea.md): 예산표 절차, 점 8개의 이웃 목록과 4 × 4 칸 손계산, 후보를 줄였을 때 놓치는 이동과 작업 6개·기계 4대 손계산, 남은 비율 표, 시계 읽기 모형.
2. [구현: 후보 목록·예산 틀과 두 문제 유형](pages/implementation.md): 문제와 무관한 `Plan`·`climbPlan`·`sweepAll`·`byRemaining`과 문제마다 채우는 칸·이웃 목록·`cand`를 두 유형에서 구현합니다.
3. [실험과 점검](pages/practice.md): 예산이 쓰이는 곳, 후보 수별 비교, 놓치는 이동, 단계 배분, 예산과 품질, 시계 간격, 자기 환경에서 재는 방법, 흔한 실수와 검사, 점검 목록, 적용 사례.

## 로컬 연습

1. 구현 페이지의 `Route`로 후보 `k = 8`을 예산 400,000과 2,000,000에서 시드 1~20으로 돌려 실험 페이지의 값과 맞춥니다.
2. 칸 탐색의 종료 조건을 한 겹 일찍 끊게 바꿔 전수 목록과 처음 달라지는 점을 찾습니다.
3. 후보 수 4·8·16을 예산 세 가지에서 짝지어 비교하고 "더 좋음·더 나쁨·결정 못 함"을 판정합니다.
4. 시계 버전 루프로 자기 환경의 연산 하나의 시간과 시계 읽기 비용을 재고 읽기 간격을 정합니다.
