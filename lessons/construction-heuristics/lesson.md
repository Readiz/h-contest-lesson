# 초기해 만들기: 탐욕·삽입·무작위화

해 전체를 한 번에 정하기는 어렵지만 "남은 것 중 하나를 골라 자리에 놓는" 일은 쉬운 문제가 많습니다. 이 일을 남은 것이 없을 때까지 반복해 완성된 해를 만드는 방법을 **구성법**이라고 합니다. 구성법의 결과는 최적이 아닐 수 있지만, 항상 유효한 해를 빠르게 주고 뒤에 붙는 개선 탐색의 출발점이 됩니다. [그리디 알고리즘](https://h.readiz.com/learn/greedy)은 이런 선택이 최적이 되는 조건을 증명하는 강의이고, 이 강의는 증명 없이 쓰는 구성법을 비교하고 고르는 방법을 다룹니다.

[휴리스틱 입문](https://h.readiz.com/learn/heuristic)과 [그리디 알고리즘](https://h.readiz.com/learn/greedy)을 읽었다고 가정합니다. 문제를 상태·행동·점수로 옮기는 일은 [문제를 상태·행동·점수로 옮기기](https://h.readiz.com/learn/problem-modeling)에서 다루며, 난수와 정렬은 [공통 코드](https://h.readiz.com/learn/cpp-common-library)의 `random`, `sort` 블록을 앞에 붙여 씁니다.

## 이 강의에서 다루는 것

- 고르기 → 자리 정하기 → 상태 갱신의 공통 틀과 선택 기준(가까운 것, 싸게 끼울 자리, 후회, 큰 것부터)의 비교.
- 기준을 조금 흔드는 무작위화와 여러 번 만들어 가장 좋은 것을 고르는 방법, 그 평가 횟수와 이득.
- 기계당 `K`개 같은 유효성 제약을 후보 만들기에서 지키는 방법.
- 초기해의 질이 단순한 개선 뒤의 결과에 주는 영향. 이동의 설계는 [근방 설계와 차분 평가](https://h.readiz.com/learn/neighborhood-and-delta), 더 강한 탐색은 [언덕 오르기와 담금질](https://h.readiz.com/learn/hill-climbing-and-annealing), 구성법을 부순 뒤 다시 짓는 데 쓰는 방법은 [크게 부수고 다시 짓기](https://h.readiz.com/learn/destroy-and-repair)에서 다룹니다.

## 판단 기준 요약

| 상황 | 고를 기준 |
| --- | --- |
| 자리가 하나뿐이고 가까운 것을 잇는 구조 | 가장 가까운 것(평가 횟수가 가장 적음) |
| 중간에 끼울 자리가 여럿인 구조 | 가장 싸게 끼울 자리, 후회, 가장 먼 것부터 |
| 항목마다 자리별 비용 차이가 크고 자리가 제한됨 | 후회가 큰 것부터 |
| 크기 순서가 결과를 좌우하는 채우기 | 큰 것부터 같은 정렬 기준 |
| 한 번 만드는 비용이 매우 작고 결과가 흩어짐 | 첫 항목이나 기준을 흔들어 여러 번 |

## 로컬 연습 과제

1. 입력 시드 21~30으로 순서 틀의 가장 가까운 점 잇기와 후회 삽입의 구성 직후 비용 중앙값을 구해 표와 같은 순위인지 확인합니다.
2. 순서 틀에서 경로의 양 끝에 모두 붙일 수 있는 가장 가까운 점 잇기를 `candidates`만 바꿔 구현하고, 평가 횟수와 비용을 비교합니다.
3. 배정 틀에서 후회의 `second`를 `best`로 바꾼 변형(후회 0)을 만들어 `K = 15`에서 비용이 어떻게 바뀔지 먼저 예측한 뒤 측정합니다.
4. 새 문제 하나를 골라 `begin`, `remaining`, `candidates`, `place` 네 함수만 채워 보고, 점검 목록에 답을 적습니다.
