# 문제를 상태·행동·점수로 옮기기

처음 보는 휴리스틱 문제에서 개선 방법을 고르기 전에 할 일은 문제 설명을 코드가 계산할 수 있는 모양으로 옮기는 것입니다. 무효한 답은 점수를 받지 못하고, 점수식을 잘못 읽으면 이후의 모든 개선을 틀린 기준으로 비교하게 됩니다. 이 강의는 문제 설명(계약)에서 상태·행동·무효 조건·불변식을 뽑아 표로 정리하고, 내 점수 계산을 채점과 맞추고, 유효한 기준선을 만들고, 점수의 한계로 남은 여지를 가늠하는 절차를 다룹니다. 문제가 바뀌어도 절차는 같고 표의 내용만 달라집니다.

선수 강의는 [실전 C++ 제출과 검증](https://h.readiz.com/learn/cpp-contest-basics)입니다. 예시는 순서, 배정, 격자 수집이라는 연습용 문제 틀 세 가지만 쓰고, 이 사이트의 실제 문제는 [적용 사례](pages/practice.md)에서 강의 링크로만 가리킵니다.

## 이 강의에서 다루는 것

- 계약의 문장을 입력·답·상태·무효 조건·불변식·점수의 표로 옮기는 절차.
- 유효 판정과 점수를 따로 만들어 채점(여기서는 참조 채점)과 맞추는 방법.
- 어떤 입력에서도 유효한 가장 단순한 기준선을 먼저 만드는 이유와 방법. 기준선은 유효함까지만 다루고, 좋은 초기해는 [초기해 만들기](https://h.readiz.com/learn/construction-heuristics)에서 다룹니다.
- 점수의 하한·상한으로 더 좋아질 수 있는 폭의 위쪽 경계를 구하는 방법과 한계 계산을 검사하는 방법.
- TC(테스트 케이스, 입력 하나) 여러 개를 이어 푸는 문제에서 상태를 초기화하는 원칙.

## 판단 기준 요약

| 상황 | 이 절차 |
| --- | --- |
| 처음 보는 문제, 점수식이 두 항 이상 | 다섯 단계 모두 |
| 무효한 답이 0점이거나 거절되는 문제 | `valid`를 먼저 만들고 기준선으로 검증 |
| TC를 한 프로세스에서 연달아 푸는 문제 | TC 시작마다 상태를 비우고 이어 푼 결과를 따로 푼 결과와 대조 |
| 점수를 반복마다 다시 계산하면 느린 탐색 | 전체 재계산은 정답지로만 쓰고 탐색 안에서는 변화량만 계산 |
| 한계가 느슨한 문제 | 한계를 목표가 아니라 여지의 크기를 보는 용도로만 |

## 대표 실험 결과

기본 크기의 연습용 입력 시드 1~10에서 기준선 점수가 한계의 몇 배인지입니다(1에 가까울수록 더 좋아질 여지가 작습니다). 시드마다의 값과 작은 입력에서 한계를 최적과 비교한 표는 [실험과 실수](pages/practice.md)에 있습니다.

## 본문

1. [원리와 손계산](pages/idea.md): 연습용 문제 틀의 규칙, 다섯 단계, 언제 쓰고 언제 쓰지 않는가, 작업 6개·기계 3대 손계산, TC 사이에 남기지 않는 상태.
2. [코드 틀과 세 가지 적용](pages/implementation.md): 문제와 무관한 틀(`pm`)과 문제마다 채우는 모델(순서·배정·격자 수집)의 제출용 코드.
3. [실험과 실수](pages/practice.md): 참조 채점과의 대조, 기준선 경계, 한계 검사, 흔한 실수와 검사 방법, 다른 문제에 옮길 때의 점검 목록, 적용 사례.

## 로컬 연습

1. 순서 틀을 위 규칙으로 시드 1에서 만들고, 번호 순서 기준선의 비용과 최소 신장 트리 하한을 손이나 짧은 코드로 구해 표의 값과 맞춥니다.
2. 배정 틀의 `score`를 기계마다 100으로 나누도록 일부러 바꾸고, 어떤 답에서 참조 점수와 어긋나는지 찾습니다.
3. 격자 수집 틀의 기준선을 항상 오른쪽으로만 가도록 바꾸고, 어떤 `H × W`, `T`에서 무효가 되는지 확인합니다.
4. 자기가 아는 다른 문제의 계약을 읽고 [코드 틀](pages/implementation.md)의 표(`Case`, `Answer`, `reset`, `valid`, `score`, `baseline`, `bound`)를 채워 봅니다.
