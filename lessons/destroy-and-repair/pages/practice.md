# 실험과 점검: 부수고 다시 짓기의 효과, 크기, 흔한 실수

[구현](implementation.md)의 코드를 연습용 문제 틀(순서 `N = 200`, 배정 `N = 120, M = 8, K = 18`, 정의는 [원리](idea.md))에서 시드 1~20으로 돌린 결과입니다. 모든 표는 `scripts/check_destroy_and_repair.py`가 다시 계산해 `lesson-assets/measurements.json`과 이 본문에 대조합니다. 시간(ms)은 싣지 않고 연산 수로 말하며, 모든 계산이 정수라서 환경이 달라도 같은 값이 나옵니다.

## 실측

측정 방법은 다음과 같습니다.

- **연산 수:** [3번 강의](https://h.readiz.com/learn/neighborhood-and-delta)와 같습니다. 반복(제안) 한 번에 1, 점수식의 항 하나를 계산할 때마다 1, 해 배열의 원소를 쓸 때마다 1입니다. 비교와 난수, 캐시 갱신은 세지 않고, 시작 비용 계산은 예산에 넣지 않습니다.
- **세 가지 방식:** "작은 이동만"은 3번 강의의 이동(순서 틀은 구간 뒤집기와 한 점 옮기기, 배정 틀은 한 작업 옮기기와 두 작업 맞바꾸기)을 좋아질 때만 받으며 예산 전부에 씁니다. "부수고 다시 짓기만"은 시작 해(번호 순서, 라운드 로빈)에서 곧바로 부수고 다시 짓습니다. "혼합"은 예산의 1/4을 작은 이동에 쓰고 나머지를 부수고 다시 짓기에 씁니다. 부수고 다시 짓기의 기본 설정은 순서 틀이 "가까운 점 8개, 가장 싼 자리, 좋아질 때만", 배정 틀이 "무작위 작업 8개, 후회 기준, 좋아질 때만"입니다. 이 기본 설정은 아래 표의 몇 가지를 같은 시드로 훑어 골랐으므로 시드 1~20에서의 비교는 설정을 고른 만큼 낙관적일 수 있습니다. 그래서 끝에서 고르는 데 쓰지 않은 시드 21~40으로 한 번 더 확인합니다.
- **요약:** 표의 값은 시드 20개의 최종 비용 중 10번째로 작은 값(중앙값의 아래쪽)입니다. 시작 비용은 순서 틀이 131,115, 배정 틀이 47,295입니다. 두 설정의 비교는 같은 시드끼리 짝지어 "앞이 나은 시드 / 뒤가 나은 시드"를 셉니다.
- **판정:** 한쪽이 20개 중 15개 이상에서 나으면(부호 검정의 양쪽 유의확률 0.041) 차이가 있다고 쓰고, 아니면 "결정 못 함"이라고 씁니다. 이 판정은 이 입력 가족과 이 예산에 한정됩니다. 어느 방법이 다른 입력 가족에서도 이긴다는 뜻이 아닙니다.

### 작은 이동의 지역 최적에서

시작 해에서 한 점 옮기기와 구간 뒤집기(배정 틀은 한 작업 옮기기와 두 작업 맞바꾸기)의 근방을 전부 훑어 개선 이동이 하나도 없을 때까지 적용해 지역 최적을 만듭니다(비용 중앙값은 순서 틀 14,193, 배정 틀 43,974이고, 시드 20개 모두 개선하는 이동이 없음을 따로 다시 확인했습니다). 이 해에서 부수고 다시 짓기를 300번 시도해(받지 않고 되돌리기만 함) 새 해가 지금보다 좋았던 횟수를 셉니다. 칸의 값은 "300번 중 개선한 횟수의 중앙값 / 개선을 한 번이라도 찾은 시드 수(20개 중)"입니다. 다시 짓기는 가장 싼 자리입니다.

순서 틀입니다.

| 떼어 내는 점 수 | 무작위 | 연속 구간 | 가까운 점 | 비용 기여 |
| ---: | ---: | ---: | ---: | ---: |
| 1 | 0 / 0 | 0 / 0 | 0 / 0 | 0 / 0 |
| 2 | 0 / 1 | 5 / 19 | 5 / 19 | 0 / 2 |
| 3 | 0 / 6 | 15 / 20 | 11 / 20 | 0 / 4 |
| 5 | 1 / 11 | 25 / 20 | 25 / 20 | 1 / 12 |
| 8 | 2 / 20 | 43 / 20 | 36 / 20 | 2 / 16 |
| 13 | 5 / 18 | 40 / 20 | 57 / 20 | 6 / 18 |
| 21 | 12 / 20 | 22 / 20 | 57 / 20 | 14 / 19 |

배정 틀입니다. 열은 다시 놓는 규칙입니다.

| 떼어 내는 것 | 가장 싼 기계 | 후회 기준 |
| --- | ---: | ---: |
| 무작위 작업 1개 | 0 / 0 | 0 / 0 |
| 무작위 작업 2개 | 0 / 1 | 0 / 2 |
| 무작위 작업 4개 | 0 / 0 | 0 / 4 |
| 무작위 작업 8개 | 0 / 1 | 0 / 6 |
| 무작위 작업 15개 | 0 / 0 | 1 / 14 |
| 기계 1대의 작업 전부 | 0 / 0 | 0 / 0 |
| 기계 2대의 작업 전부 | 0 / 0 | 8 / 13 |

- 한 점(한 작업)을 떼어 내고 가장 싼 곳에 놓는 경우는 순서 틀의 모든 부수기와 배정 틀의 무작위 1개에서 20개 시드 모두 0번입니다. 한 항목을 가장 싼 자리에 다시 놓는 일이 한 점 옮기기나 한 작업 옮기기와 같은 근방이라서 생기는 필연이며, 코드로 확인했습니다.
- 순서 틀에서 연속 구간과 가까운 점은 두 점만 떼어 내도 20개 시드 중 19개에서 개선을 찾습니다. 무작위와 비용 기여는 8개를 떼어 내야 한 번이라도 찾는 시드가 20개 중 20개와 16개가 됩니다. 이 방향은 [원리](idea.md)의 7점 예(서로 가까운 두 점을 함께 옮겨야 좋아짐)와 같습니다.
- 연속 구간은 8개에서 가장 많이 찾고(43번) 21개로 늘리면 22번으로 줄어듭니다. 크게 떼어 낼수록 다시 지은 경로가 원래 경로를 앞서기 어려워진다고 읽을 수 있습니다.
- 배정 틀에서 가장 싼 기계로 다시 놓으면 모든 크기에서 중앙값이 0번입니다. 후회 기준은 작업 15개나 기계 2대를 떼어 낼 때 중앙값이 1번과 8번이며 개선을 찾은 시드가 14개와 13개입니다. 배정 틀의 지역 최적은 비용 43,974로 시작(47,295)에서 이미 많이 내려와 있고, 개선을 찾는 시도가 드뭅니다.

### 같은 예산에서 작은 이동만과 비교

같은 연산 예산으로 세 방식을 비교합니다. 순서 틀입니다.

| 연산 예산 | 작은 이동만 | 부수고 다시 짓기만 | 작은 이동 1/4 + 부수고 다시 짓기 | 혼합이 나은 / 못한 시드 |
| ---: | ---: | ---: | ---: | ---: |
| 1,000,000 | 14,504 | 19,022 | 14,449 | 11 / 9 |
| 2,000,000 | 14,218 | 15,888 | 13,819 | 18 / 2 |
| 4,000,000 | 14,203 | 15,040 | 13,762 | 20 / 0 |

예산 안에서 돈 부수고 다시 짓기의 반복 수의 중앙값입니다.

| 연산 예산 | 부수고 다시 짓기만의 반복 수 | 혼합의 반복 수(부수고 다시 짓기 구간) |
| ---: | ---: | ---: |
| 1,000,000 | 161 | 123 |
| 2,000,000 | 325 | 248 |
| 4,000,000 | 654 | 496 |

배정 틀입니다.

| 연산 예산 | 작은 이동만 | 부수고 다시 짓기만 | 작은 이동 1/4 + 부수고 다시 짓기 | 혼합이 나은 / 못한 시드 |
| ---: | ---: | ---: | ---: | ---: |
| 400,000 | 43,990 | 44,014 | 44,042 | 3 / 17 |
| 1,000,000 | 43,990 | 43,987 | 43,984 | 13 / 5 |
| 2,000,000 | 43,990 | 43,949 | 43,957 | 18 / 2 |

배정 틀에서 돈 반복 수의 중앙값입니다.

| 연산 예산 | 부수고 다시 짓기만의 반복 수 | 혼합의 반복 수(부수고 다시 짓기 구간) |
| ---: | ---: | ---: |
| 400,000 | 442 | 334 |
| 1,000,000 | 1,111 | 849 |
| 2,000,000 | 2,234 | 1,672 |

- 순서 틀에서 부수고 다시 짓기만 쓰는 방식은 모든 예산에서 작은 이동만보다 나쁩니다(예산 4,000,000에서 15,040 대 14,203, 20개 중 18개 시드가 나쁨). 반복 하나가 점 8개 × 자리 약 200곳의 평가를 쓰기 때문에 같은 예산에서 654번밖에 돌지 못합니다. 혼합은 첫 1/4을 싼 작은 이동으로 시작 해를 지역 최적 근처까지 내린 뒤에 이 비싼 반복을 씁니다.
- 혼합은 예산이 2,000,000과 4,000,000에서 작은 이동만보다 낫습니다(18 / 2와 20 / 0, 중앙값 13,819와 13,762, 작은 이동만의 14,218과 14,203). 예산 1,000,000에서는 결정하지 못했습니다(11 / 9). 작은 이동에 쓰는 250,000이 짧아서일 수 있지만 이 실험은 원인을 가르지 않았습니다. 작은 이동만은 예산을 4배 늘려도(1,000,000 → 4,000,000) 14,504에서 14,203까지만 내려가며, 이는 지역 최적의 중앙값(14,193)에 가깝습니다.
- 배정 틀은 이득이 작습니다. 작은 이동만이 예산에 상관없이 중앙값 43,990에 머물고 혼합은 예산 2,000,000에서 43,957(18 / 2, 더 좋음)로 비용의 0.1%도 안 되는 33을 더 줄입니다. 작은 이동이 시작 47,295에서 43,990까지 3,305를 내려온 뒤라서 남은 여지가 작은 입력입니다. 예산 400,000에서는 반대로 혼합이 더 나쁩니다(3 / 17). 혼합은 작은 이동에 100,000만 쓰기 때문에 작은 이동만이 같은 예산에서 닿은 43,990에 미치지 못했습니다(44,042).

기본 설정을 고르는 데 쓰지 않은 시드 21~40에서 예산 4,000,000(순서 틀)과 2,000,000(배정 틀)의 작은 이동만과 혼합을 비교합니다.

| 틀 | 작은 이동만 | 혼합 | 혼합이 나은 / 못한 시드 | 판정 |
| --- | ---: | ---: | ---: | --- |
| 순서 틀 | 14,209 | 13,841 | 20 / 0 | 더 좋음 |
| 배정 틀 | 45,605 | 45,596 | 17 / 2 | 더 좋음 |

방향은 시드 1~20과 같습니다. 배정 틀은 이 시드들에서 비용이 달라 절대 값은 다르고, 차이(9)는 비용의 0.02%입니다.

### 부술 부분 고르기

혼합(작은 이동 1/4 + 부수고 다시 짓기)에서 부수는 방법만 바꿉니다. 기준은 무작위입니다. "받은 횟수"는 다시 지은 해를 받은 횟수의 중앙값입니다(좋아질 때만 받으므로 개선 횟수와 같습니다).

순서 틀(점 8개)입니다.

| 부수기 | 비용 | 무작위보다 나은 / 못한 시드 | 판정 | 받은 횟수 |
| --- | ---: | ---: | --- | ---: |
| 무작위 | 14,202 | - | 기준 | 7 |
| 연속 구간 | 13,788 | 20 / 0 | 더 좋음 | 17 |
| 가까운 점 | 13,762 | 20 / 0 | 더 좋음 | 20 |
| 비용 기여 | 14,233 | 8 / 11 | 결정 못 함 | 7 |

배정 틀입니다. 기계 1대는 작업 약 15개, 2대는 약 30개를 떼어 냅니다.

| 부수기 | 비용 | 무작위보다 나은 / 못한 시드 | 판정 | 받은 횟수 |
| --- | ---: | ---: | --- | ---: |
| 무작위 작업 8개 | 43,957 | - | 기준 | 6 |
| 기계 1대의 작업 전부 | 43,990 | 0 / 20 | 더 나쁨 | 0 |
| 기계 2대의 작업 전부 | 43,974 | 5 / 15 | 더 나쁨 | 2 |
| 비용 기여 작업 8개 | 43,967 | 11 / 9 | 결정 못 함 | 6 |

- 순서 틀에서 서로 가까운 것(연속 구간, 가까운 점)이 무작위보다 20개 시드 모두에서 낫습니다. 무작위 8개의 14,202는 작은 이동만(14,203)과 같은 수준이라, 흩어진 점을 떼어 내 다시 놓는 일은 작은 이동 몇 번과 비슷했다고 읽을 수 있습니다. 이 해석은 원인을 가르는 실험(흩어진 점을 어디에 놓느냐 등)을 하지 않았으므로 추론입니다.
- 비용 기여는 무작위와 결정하지 못했습니다. 기여가 큰 점은 서로 멀리 흩어져 있기 쉬워 무작위와 비슷하게 작용했을 수 있습니다. 그리고 큰 것을 더 확실히 고르게 하는 극단, 곧 모든 위치를 훑어 기여가 가장 큰 점을 고르는 코드(아래 흔한 실수 4번)는 같은 설정에서 비용 14,388로, 무작위(14,202)보다 20개 시드 모두에서 나빴습니다(0 / 20). 같은 해에서 늘 같은 부분을 떼어 내 새로운 해를 찾지 못했기 때문으로 읽을 수 있습니다.
- 배정 틀에서는 기계 단위가 무작위 작업보다 나빴습니다. 기계 1대는 받은 횟수가 0이고 비용이 작은 이동만의 결과(43,990)에서 변하지 않았습니다. 점수식이 묶음 단위로 짜여 있어도 묶음 단위로 떼어 내는 것이 이긴다고 일반화할 수 없다는 점을 보입니다. 이유는 가르지 않았습니다.

### 다시 짓는 구성법

부수는 방법 두 가지에서 다시 짓는 규칙(가장 싼 자리와 후회 기준)만 바꿉니다. 기준은 가장 싼 자리입니다.

순서 틀(점 8개)입니다.

| 부수기 | 다시 짓기 | 비용 | 반복 수 | 가장 싼 자리보다 나은 / 못한 시드 | 판정 |
| --- | --- | ---: | ---: | ---: | --- |
| 가까운 점 | 가장 싼 자리 | 13,762 | 496 | - | 기준 |
| 가까운 점 | 후회 기준 | 13,874 | 135 | 3 / 17 | 더 나쁨 |
| 연속 구간 | 가장 싼 자리 | 13,788 | 512 | - | 기준 |
| 연속 구간 | 후회 기준 | 13,811 | 136 | 9 / 11 | 결정 못 함 |

배정 틀입니다.

| 부수기 | 다시 짓기 | 비용 | 반복 수 | 가장 싼 자리보다 나은 / 못한 시드 | 판정 |
| --- | --- | ---: | ---: | ---: | --- |
| 무작위 작업 8개 | 가장 싼 자리 | 43,983 | 6,703 | - | 기준 |
| 무작위 작업 8개 | 후회 기준 | 43,957 | 1,672 | 16 / 3 | 더 좋음 |
| 기계 2대 | 가장 싼 자리 | 43,990 | 1,786 | - | 기준 |
| 기계 2대 | 후회 기준 | 43,974 | 134 | 17 / 0 | 더 좋음 |

- 후회 기준은 평가가 크기에 비례해 더 들어 같은 예산의 반복이 줄어듭니다(순서 틀 496번 대 135번, 배정 틀 6,703번 대 1,672번). 순서 틀에서는 그 손해가 더 컸고(3 / 17) 연속 구간에서는 결정하지 못했습니다. 배정 틀에서는 반복이 4배에서 13배 줄어도 후회 기준이 더 좋았습니다(16 / 3, 17 / 0).
- 앞의 지역 최적 표에서 가장 싼 기계로 다시 놓는 설정은 어느 크기에서도 개선을 거의 찾지 못했고 후회 기준은 찾았습니다. 배정 틀에서 후회 기준의 비싼 평가가 값을 한 이유로 읽을 수 있으나, 같은 표를 순서 틀에는 후회 기준으로 만들지 않아 두 틀의 차이를 가르지는 못했습니다.
- 어느 쪽이 이길지는 문제와 예산에 따라 달라지므로 두 규칙을 모두 같은 예산에서 재 보는 것이 방법입니다.

### 받는 기준

혼합의 기본 설정에서 받는 기준만 바꿉니다. 담금질식의 온도는 시작 온도 `t0`에서 예산이 줄어드는 만큼 선형으로 0까지 내리며, 온도의 범위를 정하는 방법은 [언덕 오르기와 담금질](https://h.readiz.com/learn/hill-climbing-and-annealing)에서 다루기 때문에 여기서는 몇 가지 값만 시험했습니다. "받은 횟수"는 받은 반복의 중앙값입니다.

순서 틀입니다.

| 받는 기준 | 비용 | 기준보다 나은 / 못한 시드 | 판정 | 받은 횟수 |
| --- | ---: | ---: | --- | ---: |
| 좋아질 때만 | 13,762 | - | 기준 | 20 |
| 같아도 받기 | 13,686 | 5 / 1 | 결정 못 함 | 246 |
| 담금질식, 시작 온도 30 | 13,717 | 14 / 6 | 결정 못 함 | 301 |
| 담금질식, 시작 온도 300 | 13,666 | 10 / 10 | 결정 못 함 | 428 |
| 담금질식, 시작 온도 1000 | 13,854 | 5 / 15 | 더 나쁨 | 467 |

배정 틀입니다.

| 받는 기준 | 비용 | 기준보다 나은 / 못한 시드 | 판정 | 받은 횟수 |
| --- | ---: | ---: | --- | ---: |
| 좋아질 때만 | 43,957 | - | 기준 | 6 |
| 같아도 받기 | 43,971 | 11 / 5 | 결정 못 함 | 1,252 |
| 담금질식, 시작 온도 1 | 43,950 | 14 / 5 | 결정 못 함 | 1,271 |
| 담금질식, 시작 온도 10 | 43,971 | 14 / 6 | 결정 못 함 | 1,274 |
| 담금질식, 시작 온도 100 | 43,990 | 2 / 18 | 더 나쁨 | 1,481 |

- 같아도 받기와 온도가 낮은 담금질식은 두 틀 모두 좋아질 때만 받기와 결정하지 못했습니다. 받은 횟수는 순서 틀에서 20번에서 246번으로, 배정 틀에서 6번에서 1,252번으로 늘었지만 비용은 시드 흔들림 안에 있습니다. 늘어난 받은 횟수 중에서 다시 지은 해가 부수기 전과 같아서 받은 경우가 얼마인지는 세지 않았습니다.
- 온도가 높으면 두 틀 모두 더 나빴습니다(순서 틀 시작 온도 1000에서 5 / 15, 배정 틀 100에서 2 / 18). 시작 온도를 반복의 비용 변화(Δ)의 크기에 맞추지 않으면 나쁜 해를 너무 잘 받아 예산 안에 회복하지 못합니다. 이 표의 온도 값은 이 입력에서만 쓸 수 있는 값이고, 문제가 바뀌면 Δ의 분포에서 다시 정해야 합니다(방법은 담금질 강의).

### 부수는 크기

혼합에서 떼어 내는 크기만 바꿉니다. 순서 틀은 가까운 점, 배정 틀은 무작위 작업(후회 기준)입니다. 기준은 같은 예산의 작은 이동만입니다. 크기가 순서 틀의 200과 배정 틀의 120일 때는 해 전체를 떼어 내고 처음부터 다시 짓는 것과 같습니다.

순서 틀입니다. 열은 떼어 내는 점 수, 비용, 반복 수의 중앙값, 받은 횟수의 중앙값, 작은 이동만과의 비교, 판정입니다.

| 떼어 내는 점 수 | 비용 | 반복 수 | 받은 횟수 | 작은 이동만보다 나은 / 못한 시드 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 작은 이동만 | 14,203 | - | - | - | 기준 |
| 1 | 14,336 | 2,318 | 4 | 1 / 16 | 더 나쁨 |

| 5 | 13,966 | 743 | 18 | 20 / 0 | 더 좋음 |
| 8 | 13,762 | 496 | 20 | 20 / 0 | 더 좋음 |
| 13 | 13,662 | 321 | 23 | 20 / 0 | 더 좋음 |
| 21 | 13,716 | 209 | 17 | 20 / 0 | 더 좋음 |
| 40 | 13,816 | 117 | 7 | 18 / 2 | 더 좋음 |
| 80 | 14,285 | 67 | 2 | 8 / 12 | 결정 못 함 |
| 200 | 14,504 | 43 | 0 | 0 / 20 | 더 나쁨 |

배정 틀입니다.

| 떼어 내는 작업 수 | 비용 | 반복 수 | 받은 횟수 | 작은 이동만보다 나은 / 못한 시드 | 판정 |
| --- | ---: | ---: | ---: | ---: | --- |
| 작은 이동만 | 43,990 | - | - | - | 기준 |
| 1 | 43,990 | 51,720 | 0 | 0 / 11 | 결정 못 함 |
| 2 | 43,990 | 18,518 | 1 | 4 / 4 | 결정 못 함 |
| 4 | 43,990 | 5,837 | 3 | 13 / 2 | 결정 못 함 |

- 두 틀 모두 가운데 크기가 이깁니다. 순서 틀은 점 3개에서 40개까지(전체의 1.5%에서 20%) 작은 이동만보다 낫고 점 13개(6.5%)에서 가장 낮았으며, 배정 틀은 작업 8개와 16개(7%와 13%)에서만 앞섰습니다. 경험 법칙인 "전체의 몇 퍼센트"에 견주면 두 틀 모두 4%에서 13% 안팎의 크기(순서 틀 8~21개, 배정 틀 8~16개)가 좋은 쪽이었고 방향이 맞지만, 한 가지 예산과 한 가지 설정에서의 결과입니다.
- 크기 1은 가장 싼 자리로 한 점을 옮기는 것이라 작은 이동의 지역 최적을 못 벗어납니다. 순서 틀에서는 작은 이동만보다 오히려 나쁘고(1 / 16), 배정 틀에서는 20개 중 9개 시드에서 같은 비용이고 11개에서 나빠서(0 / 11) 결정하지 못했습니다.
- 크기를 전체로 하면 반복 수가 순서 틀에서 2,318번에서 43번으로 줄고, 처음부터 다시 지은 해가 작은 이동의 결과(예산 1,000,000에서 얻은 14,504)보다 좋았던 적이 한 번도 없습니다(받은 횟수 0, 14,504가 그대로 남음).
- 배정 틀에서 작업 32개 이상은 받은 횟수의 중앙값이 0이고 비용이 작은 이동만의 결과(43,990)와 같습니다. 순서 틀에서도 80개 이상은 결정하지 못하거나 나쁩니다.

### 되돌리는 방법

배정 틀에서 복사 방식과 기록 방식을 같은 예산(2,000,000)의 부수고 다시 짓기만으로 비교합니다. 두 방식은 같은 제안을 같은 순서로 받고 거절하므로 같은 반복 수에서는 같은 해에 닿습니다(4가지 설정 × 시드 5개의 20번 모두 고정 반복 400번 뒤 해가 같고, 기록 쪽이 쓴 연산이 적었습니다). 그래서 같은 예산에서의 차이는 반복 수로 나타납니다. "반복당 쓰기"와 "반복당 연산"은 시드별 값의 중앙값입니다.

| 떼어 내기 | 다시 짓기 | 되돌리기 | 반복 수 | 반복당 쓰기 | 반복당 연산 | 비용 |
| --- | --- | --- | ---: | ---: | ---: | ---: |
| 무작위 작업 8개 | 가장 싼 자리 | 복사 | 4,202 | 291 | 475 | 44,062 |
| 무작위 작업 8개 | 가장 싼 자리 | 기록 | 9,087 | 33 | 218 | 43,995 |
| 무작위 작업 8개 | 후회 기준 | 복사 | 1,737 | 291 | 1,149 | 43,960 |
| 무작위 작업 8개 | 후회 기준 | 기록 | 2,234 | 36 | 890 | 43,949 |
| 기계 2대 | 후회 기준 | 복사 | 178 | 332 | 11,158 | 44,013 |
| 기계 2대 | 후회 기준 | 기록 | 181 | 135 | 10,983 | 44,013 |

- 복사는 반복마다 해 전체(`n + 2m + 2 = 138`칸)를 저장하고 거절하면 다시 복원해 쓰기가 291번으로 늘고, 기록은 떼어 낸 작업만 되돌려 33번입니다. 다시 놓는 평가가 싼 가장 싼 자리 규칙에서는 이 차이가 반복당 연산 475대 218로 나타나 같은 예산에서 반복이 2배 넘게 돌았습니다(4,202번 대 9,087번).
- 후회 기준에서는 다시 놓는 평가가 반복당 연산의 대부분을 차지해서 차이가 줄고(1,149 대 890, 반복 1,737번 대 2,234번), 기계 2대(작업 약 30개)에서는 거의 없어집니다(반복 178번 대 181번). 다시 짓기의 평가가 반복의 대부분이면 되돌리기를 최적화해도 얻는 것이 작습니다.

반복 한 번이 쓰는 연산은 아래와 같습니다(기본 설정, 부수고 다시 짓기만 쓴 실행). 순서 틀은 새 배열에 짓기, 배정 틀은 기록 방식입니다. 세 값은 각각의 중앙값이라 합이 정확히 맞지는 않습니다.

| 틀 | 반복당 연산 | 반복당 항 계산 | 반복당 쓰기 |
| --- | ---: | ---: | ---: |
| 순서 틀 | 6,116 | 5,075 | 1,040 |
| 배정 틀 | 890 | 852 | 36 |

순서 틀은 항 계산이 대부분이고 쓰기는 6분의 1 남짓입니다. 이 틀은 부분 해를 새 배열에 만드는 쓰기가 어차피 필요해서 되돌리기에 따로 드는 쓰기가 없습니다. 항 계산이 이렇게 큰 이유는 떼어 낸 점마다 자리 약 200곳을 평가하기 때문이며, 평가할 자리를 가까운 곳으로 줄이는 방법은 [후보 줄이기와 시간 예산](https://h.readiz.com/learn/candidate-and-time-budget)에서 다룹니다.

## 흔한 실수와 잡는 검사

아래 실수는 모두 본문 코드에 직접 넣어 보고 검사가 잡는지 확인했습니다(`scripts/check_destroy_and_repair.py`가 매번 다시 수행). "첫 어긋남"은 `checkDR`이 돌려주는 첫 어긋난 반복의 번호이며 잡은 시드의 중앙값입니다.

| 실수 | 검사가 잡은 시드 | 첫 어긋남(중앙값) |
| --- | ---: | ---: |
| 복사 방식에서 캐시 복원 누락 | 20 / 20 | 1 |
| 기록 방식에서 떼어 낸 작업의 기록 누락 | 20 / 20 | 1 |
| 다시 놓을 때 기계의 여유 확인 누락(모든 기계가 가득 찬 입력) | 20 / 20 | 1 |
| 최고해를 따로 보관하지 않음(받는 기준이 나쁜 해를 받는 설정) | 순서 틀 7 / 20, 배정 틀 19 / 20 | - |
| 비용 기여가 큰 점을 결정적으로 고름 | 서로 다른 부분 1개 / 200번 | - |

1. **되돌리기 누락.** 복사 방식에서 해는 복원하면서 캐시(`load`, `cnt`, `sq`, `csum`)를 복원하지 않거나, 기록 방식에서 떼어 낸 작업의 옛 기계를 기록하지 않으면 되돌린 뒤의 해와 비용이 부수기 전과 달라집니다. 점수 하나만 비교하면 모르고 지나가기 쉬워서 `checkDR`이 되돌린 뒤 비용이 부수기 전과 같은지, 추적한 비용이 처음부터 다시 계산한 값과 같은지 반복마다 확인합니다. 두 실수 모두 20개 시드 모두에서 첫 반복(중앙값 1)에 걸렸습니다.
2. **다시 놓을 때 규칙 확인 누락.** 기계의 여유 확인(`cnt < k`)을 빼면 기계가 `K`를 넘는 무효한 해가 만들어집니다. 평소에는 여유가 많아 드물게 걸리므로 모든 기계가 가득 찬 입력(작업 24개, 기계 8대, 상한 3)에서 검사합니다. 20개 시드 모두 첫 반복(중앙값 1)에서 걸렸습니다.
3. **최고해를 따로 보관하지 않음.** 받는 기준이 나쁜 해를 받을 수 있으면 끝났을 때의 지금 해가 지나온 최선보다 나쁠 수 있습니다. 좋아질 때만 받는 설정에서는 지금 해가 최고해와 같아 드러나지 않습니다. 담금질식 설정에서 반환한 비용이 받은 해들의 최솟값과 같은지 보는 검사가 순서 틀에서 7개, 배정 틀에서 19개 시드를 잡았습니다. 받는 기준을 바꿀 때마다 이 검사를 다시 돌려야 합니다.
4. **비용 기여가 큰 것을 결정적으로 고름.** 기여가 큰 점을 항상 정확히 큰 순서대로 고르면 거절된 뒤에도 같은 해에서 같은 점들을 다시 떼어 내고 같은 결과를 얻어 탐색이 멈춥니다. 같은 해에서 200번 부수기를 불렀을 때 서로 다른 부분이 정상 코드는 200개인데 결정적으로 고르는 코드는 1개입니다. 고르는 방법에 무작위성이 있는지, 같은 해에서 여러 번 불렀을 때 다른 부분이 나오는지를 세어 보는 검사가 잡습니다.

## 다른 문제에 옮길 때 점검 목록

1. 해의 일부를 떼어 낸 부분 해가 유효한가? 떼어 낸 만큼의 자리가 항상 남아 다시 놓을 수 있는가? 다시 놓을 때 문제의 규칙(여유, 중복, 순서)을 확인하는가?
2. 떼어 낼 항목이 서로 영향을 주는 것끼리 묶이는가, 아니면 흩어져서 작은 이동과 다를 바 없는가? 같은 해에서 여러 번 불렀을 때 서로 다른 부분이 나오는가?
3. 다시 짓는 구성법이 있는가? 가장 싼 자리와 후회 기준을 같은 예산에서 재 보았는가?
4. 반복 하나의 비용(자리 수 × 떼어 내는 수)은 얼마이고 예산 안에 몇 번 도는가? 평가할 자리를 줄일 수 있는가?
5. 되돌리는 방법이 해의 표현에 맞는가(바뀌는 칸이 적으면 기록, 부분 해를 새로 만들면 새 배열)? 되돌린 뒤 해·캐시·비용이 부수기 전과 같음을 검사했는가?
6. 받는 기준이 나쁜 해를 받을 수 있으면 최고해를 따로 보관하는가? 시작 온도를 비용 변화의 크기에서 정했는가?
7. 떼어 내는 크기를 한 값으로 정하지 않고 몇 가지로 훑었는가? 크기 1은 작은 이동의 근방 안임을 확인했는가?
8. 작은 이동만 쓰는 탐색과 같은 연산 예산·같은 시드로 짝지어 비교했는가? 승패가 갈리지 않으면 "결정 못 함"으로 두고, 설정을 고르는 데 쓰지 않은 시드로도 확인했는가? ([실험과 튜닝](https://h.readiz.com/learn/experiments-and-tuning)에서 이어집니다.)

## 적용 사례

이 강의의 틀이 이 사이트의 문제에서 쓰인 곳입니다. 각 강의는 해당 문제 하나를 끝까지 푸는 방식이라 이 강의와 설명의 순서가 다릅니다.

- [격자 배치 문제(LANDINGX)](https://h.readiz.com/learn/placement-search): 점유 격자의 `put`/`take`로 만드는 되돌리기, 한 영역을 제거하고 무작위 배율로 다시 채우는 destroy/repair, 같은 후보 검사 수로 국소 이동과 비교한 실험.
- [광고판 도시 배치](https://h.readiz.com/learn/heuristic/placement-and-repair): 한 개를 옮기는 작은 이동으로 못 고치는 배치를 큰 제거 뒤 다시 채우는 서술과 손계산.
- [배정과 경로가 결합된 문제(TAXIASSIGN)](https://h.readiz.com/learn/assignment-with-routes): 승객을 다른 기사 경로의 어느 자리에 끼울지 비교하는 삽입 이동과 자리 바꾸기. 다시 짓는 구성법의 삽입 비용에 해당합니다.
- [배정 문제의 지역 탐색과 SA(SCHEDULX)](https://h.readiz.com/learn/assignment-local-search): 작업 옮기기와 맞바꾸기만으로 멈추는 구조와 부하 캐시 유지. 이 강의의 배정 틀이 같은 이동을 비교 기준으로 씁니다.

나쁜 해를 받는 규칙과 온도의 범위는 [언덕 오르기와 담금질](https://h.readiz.com/learn/hill-climbing-and-annealing)로, 후보를 가까운 곳으로 줄여 다시 짓는 평가를 줄이는 방법은 [후보 줄이기와 시간 예산](https://h.readiz.com/learn/candidate-and-time-budget)으로 이어집니다.

## 로컬 연습

1. 구현 페이지의 `runRoute`로 시드 21~30에서 작은 이동만과 혼합(가까운 점 8개)을 비교해 이 페이지의 판정 규칙대로 적습니다. 판정이 시드 1~20과 같습니까?
2. `size`를 1에서 40까지 몇 가지로 바꿔 크기 표를 직접 만들고 가장 좋은 크기를 찾습니다. 예산을 2배로 늘리면 가장 좋은 크기가 어느 쪽으로 움직입니까?
3. 순서 틀에 "무작위 한 점과 그 점의 연속한 구간에서 `size`개"를 합친 부수기를 추가하고 `checkDR`을 통과시킵니다. 서로 가까운 것을 떼어 내는 방법으로는 무엇이 더 있는지 한 가지 고안해 비교합니다.
4. 배정 틀에서 복사와 기록 방식을 각각 `useLog`로 바꿔 부수는 작업 수를 2, 8, 30으로 하며 반복당 연산을 비교합니다. 기록의 이득이 사라지는 크기는 어디입니까?
5. 담금질식의 시작 온도를 순서 틀에서 10, 30, 100, 300으로 바꿔 시드 20개로 비교하고, 나빠진 변화량(`now − cur`)의 분포를 먼저 재서 그 중앙값 근처에서 정한 값과 비교합니다.

확인 기준: 모든 변경 뒤 `checkDR`이 세 가지 입력에서 0을 돌려주고, 표의 모든 비교에 시드 수와 판정(더 좋음·더 나쁨·결정 못 함)이 붙어 있어야 합니다.
